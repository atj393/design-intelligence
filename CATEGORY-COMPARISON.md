The three `no` columns for parity are honest limits. A multi-series analysis workspace or a

in the interface** rather than hiding controls silently.

## 7. Accessibility emphasis

Every category must meet the same floor (see
[COMMON-FOUNDATION.md](COMMON-FOUNDATION.md) §13). These are the *additional* pressures.

| Category | Additional emphasis |
|---|---|
| Chat | Live-region announcements for streaming; keyboard send/stop/edit; focus management when messages append |
| Web | Heading structure; skip links; link purpose from text alone |
| Mkt | Contrast over imagery; reduced motion; autoplay controls |
| Plat | Role changes announced; permission states explained not just disabled |
| Dash | Keyboard table navigation; status never colour-only; dense targets still ≥44px on touch |
| Dev | Copy actions labelled; code blocks reachable and readable by screen readers |
| Com | Price and availability programmatically associated with the product; error recovery in checkout |
| Fin | Error prevention (WCAG 3.3.4); no time-outs without warning and extension; confirmation before irreversible actions |
| Edit | Reading order; 200% zoom reflow; sufficient measure and leading |
| Data | Chart data available as a table; series distinguishable without colour |
| Spat | Non-map alternative for map-only information; keyboard pan/zoom/select |

The inversion here is worth sitting with: the categories most in demand for new software are

they should be validated against real users earlier and harder than the marketing guide
needs to be.

## 9. Choosing between similar categories

**Dashboard vs. Data Analytics** — Dashboard *monitors known questions*: fixed metrics,
status, alerts, act-on-exception. Analytics *explores unknown questions*: pivoting,
comparing, segmenting, ad-hoc. If users mostly read prepared views, it is a dashboard. If
they mostly build their own, it is analytics.

**General Website vs. Marketing Website** — If the page's success is measured in
comprehension, it is a general website. If measured in conversion, it is marketing. Same
company, often both. Documentation is always the former even when it lives on a marketing
domain.

**Marketing vs. E-commerce** — Marketing persuades toward a single next step. E-commerce
supports comparison across many items and then a transaction. A pricing page is marketing; a
catalogue is commerce.

**Multi-Role Platform vs. Dashboard** — Count the roles. One or two roles with similar needs
is a dashboard. Three or more with materially different tasks, permissions, and vocabularies
is a platform, and the shared-foundation problem becomes the main design problem.

**Financial/High-Trust as primary vs. supporting** — Primary when the product's *core* job
involves money, identity, security, or legally significant records. Supporting when a
mostly-ordinary product contains some high-consequence flows — which is most products with a
billing page.

**Conversational AI as primary vs. supporting** — Primary when conversation is how the work
gets done. Supporting when conversation assists work done elsewhere. Getting this wrong in
the "primary" direction is how products end up as a chat box bolted onto an application that
needed a better form.
